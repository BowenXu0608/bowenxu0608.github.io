# Empty pack managers: measured result (0.6.131-test, November 10, 2026)

The fix chosen by the [audit](audit.md): `Assets/Scripts/Polar/Gameplay/PolarPackManagers.cs` sets empty instances of the pack's `SaveableDatabase`, `BuildingManager` and `PoolManager` at the first start-up stage, so the pack never reads the two manager assets or the 76 prefabs behind them. Package `Builds/HdrpMilestones/pm-02`; Development twin `pm-02-dev`. Sizes are binary (1 GiB = 1,024 MB) unless marked GB.

## Checks the audit asked for

- **The two roots are gone.** `owners-by-root.csv` has no row for `Manager<SaveableDatabase>` or `Manager<BuildingManager>` on the front page or in open snow.
- **Nothing else loads the Managers folder.** None of the marker assets (`Workbench_NRM`, `BuildingLogs_NRM`, `Marlin336_NRM`, `HuntingAxe_NRM`, `STP_Ambient_ForestNight` and others) is loaded on the front page, held or unheld. That settles the open question about the pool manager's folder search: with its instance seeded, the search is never made.
- **What the game uses still loads.** In play `MaleSurvivorSkin`, `Rock3_NRM` and `Rock5_NRM` are present, held by the game's own assets.
- **The pack's files are untouched.** `SaveableDatabase.asset` and `BuildingManager.asset` hash the same before and after the builds.
- **The package's start-up table** lists `PolarPackManagers.Seed` at stage 4 (`SubsystemRegistration`), ahead of the pack's two hooks at stage 3 and the pool manager's at stage 1.
- **No exception line** in any Player log.

## Not measured

- The one-off load at the first handbook opening and at the first sight of Frost, Moss or Shaw. The handbook, handbook-revision, ui and gameplay modes, which open the handbook and meet explorers, pass; no mode times a single worst frame there.
- A release build's memory by snapshot (the snapshots are from Development builds; the suite's peaks above are from the release package).
- Editor Play Mode was not run with the new class.

## Capture tool

Both captures taken after the return to the front page had crashed inside Unity's own snapshot code in two of five runs. They now wait two seconds first (`PolarMemoryCapture.Take(..., settle)`); the run on `pm-02-dev` completed all ten captures. One clean run does not prove the fault gone.
